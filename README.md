# 🌳 Process Tree Visualizer

> **OS-Level Parent–Child Process Mapping & Real-Time Monitoring Tool**

A full-stack diagnostic application that enumerates every running process on a Windows machine using native Win32 APIs, builds the parent-child hierarchy, and presents it through a modern, interactive web interface — complete with tree view, force-directed graph, search, filtering, sorting, and process termination.

## 🛠️ Tech Stack

| Layer      | Technology                                              |
|------------|---------------------------------------------------------|
| **Backend**| C (Win32 API — Tool Help, PSAPI), compiled with GCC     |
| **Bridge** | Node.js (built-in `http`, `child_process`, `os`, `fs`)  |
| **Frontend**| Vanilla HTML5, CSS3 (custom properties), JavaScript (ES6+) |

## 🚀 How to Run

```bash
# 1. Clone or navigate to the project directory
cd "Os project"

# 2. Start the server (compiles C backend automatically)
node server.js

# 3. Open in browser
#    → http://localhost:3000
```

The server will:
1. **Compile** `backend/process_tree.c` → `backend/process_tree.exe` (skips if already up-to-date)
2. **Start** an HTTP server on port `5500`
3. **Serve** the frontend at `/` and the API at `/api/*`

## 📡 API Endpoints

| Method | Endpoint            | Description                                      |
|--------|---------------------|--------------------------------------------------|
| GET    | `/api/processes`    | Execute C backend and return full process tree JSON |
| GET    | `/api/system`       | System metrics — CPU cores, RAM, uptime, hostname |
| GET    | `/api/history`      | Last 20 snapshots of process count trends         |
| GET    | `/api/status`       | Server health check                              |
| POST   | `/api/kill/:pid`    | Terminate a process by PID (with safety guards)   |

## ✨ Features

### Core
- **Tree View** — Hierarchical, collapsible process tree with indent connectors
- **Graph View** — Interactive force-directed canvas visualization with physics simulation
- **Real-Time Refresh** — Manual or auto-refresh (3s / 5s / 10s / 30s intervals)

### Process Inspection
- **Process Details Panel** — PID, PPID, status, threads, memory, CPU time, priority, children list
- **Ancestry Breadcrumb** — Full parent chain for any selected process
- **Hover Tooltips** — Quick-view process info on mouseover

### Search, Filter & Sort
- **Live Search** — Filter by process name or PID with match count
- **Status Filter** — Show only Running, Sleeping, or Zombie processes
- **Sorting** — By name, PID, memory usage, or child count

### System Monitoring
- **CPU & RAM Gauges** — Animated ring charts with percentage usage
- **System Uptime** — Formatted duration display
- **Process Trend Sparkline** — SVG mini-chart of process count history

### Actions
- **Kill Process** — Terminate any non-system process with confirmation dialog
- **Export JSON** — Download the full process tree as a JSON file

### UI/UX
- **Dark / Light Theme** — Toggle with preference persistence (localStorage)
- **Keyboard Shortcuts** — `R` refresh, `E/C` expand/collapse, `Ctrl+F` search, `?` help
- **Responsive Design** — Adapts from desktop to mobile layouts
- **Glassmorphism UI** — Backdrop blur, glowing accents, animated background grid

## 🔧 How It Works (Data Flow)

1. **User clicks Refresh** (or auto-refresh fires)
2. **Frontend** sends `GET /api/processes` to the Node.js server
3. **Server** executes `process_tree.exe` with output path `data/process.json`
4. **C Backend** calls `CreateToolhelp32Snapshot()`, walks every process entry, builds a hash-table-backed parent-child tree, and writes structured JSON
5. **Server** reads the JSON file and responds to the frontend
6. **Frontend** parses the tree, renders the collapsible tree view (and/or canvas graph), updates stats, sparkline, and system metrics
